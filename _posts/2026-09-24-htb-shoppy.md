The Nmap scan reveals three key services running on the target machine:

- **SSH (Port 22):** OpenSSH 8.4p1 on Debian 11
- **HTTP (Port 80):** nginx 1.23.1 — automatically redirects to `http://shoppy.htb/`, confirming a virtual host setup
- **HTTP (Port 9093):** Golang net/http server — exposes **Prometheus metrics** including Go runtime garbage collection statistics. This is an internal monitoring endpoint that leaks information about the application stack

**OS:** Linux (Debian 11) **Domain:** shoppy.htb

The most interesting initial findings are the **Prometheus metrics endpoint on port 9093** — exposing internal Go runtime metrics publicly — and **nginx on port 80** redirecting to `shoppy.htb`. The metrics confirm a Go-based application is running internally. We add the domain to `/etc/hosts`:

### Overview - NoSQL Injection (MongoDB)

**What is NoSQL Injection?** NoSQL injection is an attack against databases that use non-relational query formats — like MongoDB, which uses JSON-like documents and JavaScript-based queries instead of SQL. When user input is directly embedded into a MongoDB query without sanitization, an attacker can inject MongoDB operators like `$where`, `$regex`, or logical conditions (`||`) to manipulate query logic.

**How does it differ from SQL injection?** Traditional SQL injection uses SQL syntax (`' OR 1=1 --`). NoSQL injection uses the target database's own query language — in MongoDB's case, JavaScript-style operators. The payload `' || 'a'=='a` closes the current string and appends a condition that's always true, bypassing authentication checks.

**Why does a timeout/504 appear first?** When testing payloads in URL-encoded form, the server may time out trying to process certain malformed queries against MongoDB. Converting to JSON format (`Content-Type: application/json`) resolves parsing issues and reveals clearer error messages — which is how we identify the `jaeger` user from an error response.

### Overview - Ghidra Binary Reverse Engineering

**What is Ghidra?** Ghidra is a free, open-source reverse engineering framework developed by the NSA. It disassembles and decompiles binary executables into pseudo-C code, allowing analysts to understand what a program does without having its source code. It is particularly useful for analyzing custom binaries like this password manager to extract hardcoded secrets.

**Why use it here?** The password manager is a compiled binary with no source code available. By loading it into Ghidra, we can decompile the `main()` function and find where the password comparison is made — revealing the hardcoded master password.

We load the binary into Ghidra and analyze the main function:

### Overview - Docker Group Privilege Escalation

**Why is the docker group dangerous?** Members of the `docker` group can run Docker commands without `sudo`. Docker containers run as root by default, and the `-v` flag allows mounting host filesystem directories inside containers. By mounting the host's root filesystem (`/`) into a container, we gain read/write access to all host files as root from within the container — effectively bypassing all host file permissions.

**What is chroot?** `chroot` changes the apparent root directory for a process to a specified path. By running `chroot /mnt` inside the container (where `/mnt` is the mounted host filesystem), the container's shell behaves as if the host filesystem IS the root — making it feel like we're operating directly on the host as root.

### Exploiting Docker Group Access

We launch a new Alpine container with the host filesystem mounted at `/mnt`. The `--rm` flag removes the container when done, `-it` allocates an interactive terminal, and `-v /:/mnt` mounts the host root to `/mnt` inside the container. Instead of launching a shell directly, we use `chroot /mnt sh` to immediately set the host filesystem as root and drop into a shell:

```bash
docker run --rm -it -v /:/mnt alpine chroot /mnt sh
```

![](/assets/img/shoppy/Pasted_image_20260925200436.png)

We are now root with full access to the host filesystem. The root flag can now be retrieved.

1. **Reconnaissance:** Nmap identified nginx on port 80 redirecting to `shoppy.htb` and Prometheus metrics exposed on port 9093 revealing a Go backend

6. **Subdomain Fuzzing:** Used wfuzz to discover `mattermost.shoppy.htb` virtual host
7. **Mattermost Credential Discovery:** Authenticated as josh on Mattermost and found `jaeger:Sh0ppyBest@pp!` in a chat channel
8. **SSH Access:** Connected via SSH as jaeger and retrieved user flag
9. **Sudo Binary Discovery:** Found jaeger could run `/home/deploy/password-manager` as deploy via sudo

11. **Credential Extraction:** Ran password-manager as deploy with correct password to obtain `deploy:Deploying@pp!`
12. **Docker Group Escalation:** Leveraged deploy's docker group membership to mount host filesystem inside Alpine container with `chroot` for root access
13. **Full Compromise:** Obtained root shell via Docker container filesystem mount and retrieved root flag
